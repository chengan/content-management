# 数据库更新说明

## 📋 需要添加的字段

为了支持智能文章内容获取功能，需要在 `articles` 表中添加以下字段：

### 📊 SQL 更新脚本

请在您的 Supabase 数据库中执行以下 SQL 语句：

```sql
-- 为 articles 表添加内容获取相关字段
ALTER TABLE articles 
ADD COLUMN content_status TEXT CHECK (content_status IN ('pending', 'fetching', 'completed', 'failed')) DEFAULT 'pending',
ADD COLUMN fetch_attempts INTEGER DEFAULT 0,
ADD COLUMN last_fetch_attempt TIMESTAMP WITH TIME ZONE;

-- 为现有数据设置合理的默认值
UPDATE articles 
SET content_status = CASE 
    WHEN content IS NOT NULL AND LENGTH(content) > 50 THEN 'completed'
    WHEN source_url IS NOT NULL AND source_url != '' THEN 'pending'
    ELSE 'completed'
END
WHERE content_status IS NULL;

-- 创建索引以提高查询性能
CREATE INDEX idx_articles_content_status ON articles(content_status);
CREATE INDEX idx_articles_fetch_attempts ON articles(fetch_attempts);
```

### 📝 字段说明

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `content_status` | TEXT | 'pending' | 内容获取状态：pending(待获取)、fetching(获取中)、completed(已完成)、failed(失败) |
| `fetch_attempts` | INTEGER | 0 | 获取尝试次数 |
| `last_fetch_attempt` | TIMESTAMP | NULL | 最后一次尝试获取的时间 |

### 🎯 字段用途

- **content_status**: 跟踪文章内容的获取状态，用于显示状态标签和决定是否需要获取内容
- **fetch_attempts**: 记录尝试次数，避免无限重试失败的文章
- **last_fetch_attempt**: 记录最后尝试时间，用于调试和统计

### ✅ 验证更新

执行完 SQL 后，可以运行以下查询验证更新是否成功：

```sql
-- 检查字段是否添加成功
SELECT column_name, data_type, is_nullable, column_default 
FROM information_schema.columns 
WHERE table_name = 'articles' 
  AND column_name IN ('content_status', 'fetch_attempts', 'last_fetch_attempt');

-- 查看各状态的文章数量
SELECT content_status, COUNT(*) as count 
FROM articles 
GROUP BY content_status;
```

### 🔧 如果更新出错

如果执行过程中出现错误，可能的解决方案：

1. **权限问题**：确保您有 ALTER TABLE 权限
2. **字段已存在**：如果提示字段已存在，可以跳过 ALTER TABLE 语句
3. **约束冲突**：如果有约束冲突，先检查现有数据
