# AI改写逻辑优化说明文档

## 优化内容

### 1. 移除传统分段策略
**之前**: 支持4种分段策略（语义分段、长度分段、结构分段、AI智能分段）
**现在**: 仅支持AI智能分段

**原因**: 
- 用户反馈希望只使用大模型进行智能分段
- 简化用户操作，避免选择困扰

### 2. 修复模型选择问题
**问题**: 用户在UI选择deepseek模型，但后端仍使用gpt-3.5
**解决**: 
- 确保前端选择的模型ID正确传递到后端
- 移除所有硬编码的默认模型设置
- 强制要求用户在AI分段时指定模型

### 3. 优化OpenRouter API调用
**改进**:
- 按照OpenRouter官方文档格式调用API
- 添加详细的日志打印，方便调试
- 改进错误处理，不再自动回退到传统分段

### 4. UI界面简化
**改动**:
- 移除"分段策略"选择标签页
- 分段模型选择始终显示（因为只有AI分段）
- 更新按钮文本为"开始AI智能分段"

## 操作变化

### 改写流程（用户操作）
1. **选择素材**: 从左侧列表选择要改写的文章
2. **配置风格**: 在"风格设置"中选择改写风格和强度
3. **选择分段模型**: 在"分段模型"中选择用于分段的AI模型
4. **选择改写模型**: 在"改写模型"中选择用于改写的AI模型
5. **开始分段**: 点击"开始AI智能分段"按钮
6. **查看结果**: 分段完成后可在"分段改写"页面查看结果
7. **开始改写**: 点击"开始改写"按钮进行内容改写

### 控制台日志
现在会显示详细的处理日志：
- 🔍 开始AI智能分段分析
- 🤖 使用指定AI模型进行分段
- 🌐 发送请求到 OpenRouter API
- ✅ OpenRouter API响应成功
- 📝 AI返回内容长度
- 🔢 AI分段结果：共X个段落
- 📊 分段内容验证

## 注意事项

### 环境变量要求
确保在 `.env.local` 中配置：
```env
OPENROUTER_API_KEY=your_openrouter_api_key
```

### 模型选择建议
- **分段任务**: 推荐使用快速、经济的模型如 `mistralai/mistral-7b-instruct:free`
- **改写任务**: 推荐使用高质量模型如 `deepseek/deepseek-chat-v3.1`

### 常见问题排查
1. **分段失败**: 检查OpenRouter API密钥是否正确
2. **模型不可用**: 确认输入的模型ID在OpenRouter中存在
3. **内容丢失**: AI分段可能对长文章处理不佳，可尝试其他模型

## 技术细节

### 修改的文件
1. `src/types/rewrite.ts` - 简化SegmentStrategy类型为只有'ai'
2. `lib/rewrite-service.ts` - 移除非AI分段方法，优化AI分段逻辑
3. `app/api/rewrite/analyze-segments/route.ts` - 只允许AI分段策略
4. `src/components/rewrite/StyleSelector.tsx` - 移除分段策略选择UI
5. `app/rewrite/page.tsx` - 更新组件调用，移除segmentStrategy参数

### API调用变化
- 分段API现在强制要求 `aiModel` 参数
- `segmentStrategy` 固定为 'ai'
- 移除了分段失败的自动回退逻辑

## 测试建议

### 测试流程
1. 选择一篇中等长度文章（1000-3000字）
2. 选择免费模型进行测试：`mistralai/mistral-7b-instruct:free`
3. 观察控制台日志确认模型调用正确
4. 检查分段结果是否合理
5. 进行改写测试

### 预期结果
- 控制台显示正确的模型ID
- 分段结果符合语义完整性
- 没有"回退到语义分段"的日志
- 分段和改写都使用用户指定的模型
